# Tross

Домашний мульти-WAN балансир для мини-ПК на Debian: несколько интернет-каналов
(два проводных провайдера и LTE) работают как один надёжный «трос».
Балансировка по соединениям, отказоустойчивость, SQM (CAKE), собственный
DNS-резолвер, обход DPI (zapret) и прокси (mihomo) для доменов из списков.

Пакеты пересылает только ядро Linux (nftables, policy routing, conntrack);
демон `trossd` — плоскость управления. Если демон остановится или упадёт,
сеть не пропадает, а работает через основную таблицу маршрутизации.

## Статус

Выполнены **Этап 1 — монитор каналов и отказоустойчивость**, **Этап 2 —
классы трафика и движок решений** и **Этап 3 — очереди CAKE и
приоритеты**. Готово:

- монитор каналов: ICMP- и TCP-пробы через каждый канал, RTT, джиттер,
  потери, гистерезис, распознавание «белых списков», страниц авторизации и
  блокировки HTTP, пассивный и ночной замер скорости;
- переключение при отказе: упавший канал выводится из работы за секунды,
  его соединения сбрасываются, новые идут по живым; возврат — после
  устойчивой работы канала;
- классы трафика (игры, звонки, видео, загрузки, чувствительное к смене
  IP, свои трансляции, прочее) — по встроенным профилям сервисов (Steam,
  YouTube, Twitch, Discord, звонки, торренты, Minecraft) и своим правилам;
  у каждого класса — свой выбор канала (`ordered`, `lowest_latency`,
  `best_throughput`, `best_upload`, `balanced`), запасные каналы и
  закрепления: игра или звонок держат канал всю сессию, потоки YouTube
  устройства идут одним каналом, торренты никогда не идут через LTE;
  всё это — правилами ядра, демон пакеты не трогает;
- очереди CAKE на каждом канале в обе стороны: пинг игры под полной
  загрузкой канала растёт не больше чем на 15 мс; игры и звонки впереди
  видео, видео впереди прочего, загрузки — последними, внутри — поровну
  между устройствами дома; скорость очереди подстраивается сама по
  задержке под нагрузкой (настраивается, можно задать вручную); очереди
  остаются и без демона;
- входящие: ручные пробросы портов с защитой от частых подключений,
  ответ — в канал запроса; всё прочее из интернета в домашнюю сеть
  отбрасывается;
- наблюдение: список соединений с классом и каналом, «объясни решение» для
  устройства, адреса, домена и порта;
- история в SQLite: события, поминутная статистика каналов и машины,
  сводки по часам и дням; журнал в памяти;
- служба systemd со сторожем зависания и откатом правил при аварии.

Дальше: DNS-резолвер и списки, zapret, прокси, реестр устройств,
веб-интерфейс.

## Сборка

Нужен Go 1.26+.

```sh
make build         # bin/trossd для текущей ОС
make build-linux   # bin/linux-amd64/trossd, статический (без cgo)
make test
make lint          # gofmt, go vet (хост и linux), staticcheck
```

Без make (например, в Git Bash на Windows) — вся проверка одной командой:
`scripts/check` (форматирование, vet, staticcheck, тесты, сборка под Linux).

## Запуск в «сухом» режиме

Ничего не меняет в системе; работает и не на Linux.

```sh
./bin/trossd -config configs/example.yaml -dry-run -data-dir bin/data
curl http://127.0.0.1:8080/api/health
curl http://127.0.0.1:8080/api/links
```

## Установка на мини-ПК (Debian)

Все поля конфигурации с пояснениями — в
[configs/example.yaml](configs/example.yaml).

```sh
make build-linux
install -m 0755 bin/linux-amd64/trossd /usr/local/bin/trossd
install -D -m 0640 configs/example.yaml /etc/tross/config.yaml
install -m 0644 deploy/systemd/trossd.service /etc/systemd/system/
```

Перед запуском отредактируйте `/etc/tross/config.yaml`: в примере стоит
`daemon.dry_run: true` — так служба запустится, но ничего в сети не изменит.
Нужно `dry_run: false`, свои каналы (`links`) и домашняя сеть (`lan`). Затем:

```sh
systemctl daemon-reload && systemctl enable --now trossd
```

- Маршрут по умолчанию в основной таблице (DHCP или статика на основном
  канале) настраивает система — через него сеть работает без демона.
- `systemctl stop trossd` снимает правила балансировки и классов, но
  оставляет NAT, пробросы портов с их защитой, фильтр входящих и очереди
  CAKE: домашняя сеть продолжает работать через основной канал.
- После аварийного завершения служба снимает правила упавшего процесса
  (`trossd -cleanup`) и перезапускает демон; зависший демон перезапускает
  сторож systemd (`WatchdogSec`).
- Полное удаление правил, включая NAT и очереди: `trossd -config /etc/tross/config.yaml -purge`.

## API

Доступно только из сетей `api.allowed_networks`.

| Метод | Что отдаёт |
|---|---|
| `GET /api/health` | версия, режим, время работы |
| `GET /api/links` | каналы: состояние, RTT, джиттер, потери, скорость, очередь CAKE (скорость, база, процент) |
| `POST /api/links/{id}/speedtest` | замер скорости канала по команде |
| `GET /api/links/{id}/stats?res=minute\|hour\|day&from=&to=` | статистика канала |
| `GET /api/system/stats?res=…` | статистика машины и демона |
| `GET /api/events?since=&limit=` | события (смены состояний каналов и др.) |
| `GET /api/logs?level=&limit=` | свежие записи журнала |
| `GET /api/metrics` | самозамеры демона и машины |
| `GET /api/connections?device=&class=&link=&limit=` | соединения сейчас: класс, канал и корзина очереди из меток conntrack |
| `GET /api/explain?src=&dst=&port=&proto=&domain=` | почему соединение пойдёт так: класс, правило, закрепление, канал, корзина |

## Стенд для разработки

Сеть машины разработчика не трогается никогда. Реальный режим проверяется на
отдельной Linux-машине в закрытом стенде из сетевых пространств имён: «дом»,
«мини-ПК», три «провайдера» и «интернет» — ни одного интерфейса в настоящей
сети машины.

```sh
sudo scripts/lab-netns up            # поднять стенд (down — снять)
scripts/lab-itest 2                  # интеграционные тесты, 2 прогона с чистого стенда
scripts/lab-load 60 both             # нагрузочные сценарии с демоном и без
scripts/lab-load 60 classes          # то же с классами (configs/lab-classes.yaml)
scripts/lab-load 60 cake             # то же с очередями CAKE (scripts/lab-cake-config)
scripts/lab-soak 8h                  # длинный прогон (запускать службой, см. скрипт)
sudo scripts/lab-guard install       # сторож: перегрев, батарея, место на диске
```

С машины разработчика: `scripts/lab-sync [build|test|itest N [флаги теста]]`
— копирует рабочую копию на стенд по SSH и запускает там сборку или тесты
(например, `scripts/lab-sync itest 1 -test.run Video`).
